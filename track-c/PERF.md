## Notes

Local numbers come from a laptop (i9-13900H under WSL2, turbo on) shared with other work; they only
compare two binaries run alternately (`hyperfine`, user CPU) and read the cgroup `memory.peak`.

**Correctness first.** The spec is stricter than Python's `csv` module: quotes appear only in quoted
fields and `""` escapes come in pairs, so a byte is inside quotes exactly when an odd number of `"`
precede it. Twelve threads count quotes per chunk, a prefix parity tells every cut whether it sits
inside a quoted field, and each chunk starts after its first line break outside quotes. Byte counts are
the raw length minus one per `""`, so text is unescaped only for names that need it.

**Step 1 -> 2.** A phase profile of step 1: regions 27 ms (sorting 200k slices), chunking 13 ms (96
counting threads, oversubscribed), parse 128 ms, and a serial merge of the 12 per-thread name tables
155 ms. Partitioning names by hash and merging each partition on its own thread, a one-pass regions
reader and 12 counting threads gave board 0.334 -> 0.165 s, but memory rose to 139 MB.

**Step 3 - where the time really was.** With name interning removed (an experiment that fails the hash),
user CPU fell from 2.1 s to 0.55 s: three quarters of the work was looking names up in 12 per-thread
tables of ~100k entries and comparing bytes at random places in the 200 MB map. Each record now appends
(country, unescaped name) to a buffer per name partition - sequential writes - and each partition owner
interns only its own few thousand names in a table that stays in cache. A/B user CPU 2.4 -> 0.9 s;
board 0.165 -> 0.109 s, 139 -> 69 MB.

**Step 4 - nothing per record.** The leaders' memory (about 10 MB) showed per-record buffers were the
next cost. Now one lock-free table shared by all threads maps a name to an id (slot = hash tag and
id, compare-and-swap insert), each distinct name is copied once into a compact arena so the exact byte
comparison stays in cache, and each record sets one atomic bit (country, id). The table is sized for
the spec's pool of 100,000 names but does not rely on it: if it fills, the run repeats with a table four
times larger. The large arrays come from `calloc`, so pages that are never written cost nothing.
Board 69 -> 38 MB; T rose from 0.109 to 0.122 s (shared cache lines), and K still went up (13.3 -> 14.0).
