## Notes

Local numbers come from a laptop (i9-13900H under WSL2, turbo on) shared with other work, so they
only compare two binaries run alternately (`hyperfine`) and read the cgroup `memory.peak` the way the
board does. The same commit measured twice on the board moved between 0.0606 and 0.0736 s, so small
differences in T are noise; M and S are stable.

**Step 1.** The file is mapped, never copied: the board pre-warms it into the page cache, so a mapping
costs no memory of our own, where reading it into a buffer would cost its 239 MB. Every timestamp is
27 bytes, so the hour is the first 13 bytes; it is recomputed (integer calendar arithmetic, no date
library) only when that prefix changes, which is rare because each shard writes in time order.
Percentiles use `select_nth_unstable` on three shrinking prefixes instead of sorting each group.

**Step 2 - memory.** Step 1 parsed into packed records, then counted per group and copied every
latency into a group-ordered array: three per-line arrays alive at once. Rewriting each record in
place as `group << 33 | 5xx << 32 | latency` and sorting it per chunk leaves one per-line array; the
output walks the groups across the 12 sorted chunks. Local peak 39 MiB; board 74 -> 42.5 MB and
0.088 -> 0.072 s, with 48 fewer lines.

**Step 3 - the parse.** A local profile put the parse at most of the time (60-85 ms of ~140 ms,
loaded laptop), at about 230 ns per 77-byte line. Spaces are now found 8 bytes at a time (the classic
zero-byte test on `word ^ 0x2020...`, exact for the first match), endpoints are interned in an
open-addressing table that compares a stored hash before the bytes instead of `HashMap::entry`, and the
hour range is tracked while parsing instead of in a serial pass over 3.1M records. A/B 1.22 +/- 0.19x;
board 0.071 -> 0.061 s.
